# P10.3 AX7020 activity LED design

This design supersedes the earlier two-lane PL LED display only within the new P10.3 artifact bundle. It does not rewrite or inherit any earlier hardware PASS.

Each AX7020 uses its four active-low PL user LEDs as one monitor per installed TFDU module. LED1 reports lane0 (`F0` or `R0`), LED2 lane1 (`F1` or `R1`), LED3 lane2 (`F2` or `R2`), and LED4 lane3 (`F3` or `R3`). A lane LED is on for a final permitted physical Txd event or for a synchronized, CRC-valid remote frame accepted by the receive-admission path. Raw Rxd never drives an LED. A shared 1 ms tick provides a 200 ms visible hold. Reset, any effective full shutdown, all-four SD shutdown, or safety fault gives highest-priority `4'b1111`, so all four active-low outputs are off. These taps have no feedback or backpressure path into `GLOBAL_PERMIT`, SD, Mode, Txd kill, admission, retry, scheduling, DMA, or flow control.

The AX7020 official user manual identifies PS LED1 as `MIO0_LED`, PS MIO0 Bank 500, package pin E6, and PS LED2 as `MIO13_LED`, PS MIO13 Bank 500, package pin E8; both are low-active. The official schematic shows PS LED1 as board designator LED3 through R75 390 Ω to 3.3 V and PS LED2 as LED4 through R76 390 Ω to 3.3 V. Bank 500 uses 3.3 V. MIO0 and MIO13 are not boot straps; QSPI, Ethernet, USB, and SDIO are disabled in this runtime, while UART1 remains on MIO48/MIO49, so the frozen P10.3 mux has no identified conflict.

PS LED1 represents outstanding MM2S transmit descriptors. PS LED2 represents posted/outstanding S2MM receive descriptors. The runtime increments only after a descriptor batch is handed to hardware and the DMA engine has started, and decrements only after successful completion reclamation. Because an RX descriptor is posted before the first byte arrives, PS LED2 means “ready or receiving,” not a cycle-accurate proof that AXI data is moving. RAW commands do not use PS DMA and do not illuminate the PS LEDs.

Initialization is fail-closed for observability: output-enable is disabled first, both data latches are preloaded HIGH/off, direction is set to output, output-enable is asserted, and direction/output-enable/data readback must all show the inactive state. DMA reset, endpoint shutdown, error cleanup, command completion, and normal exit zero both in-flight counters and drive both LEDs off. A halted or crashed CPU cannot provide a hard real-time fail-dark guarantee; PS LEDs are diagnostic only and never serve as TFDU shutdown, optical success, safety, or final acceptance evidence.

The canonical machine contract is `config/hardware/p10_3_ax7020_activity_leds.yaml`.
