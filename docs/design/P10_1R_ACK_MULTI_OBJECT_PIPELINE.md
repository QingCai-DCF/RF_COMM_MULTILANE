# P10.1R ACK window and multi-object pipeline

Status: offline implementation and model; direct performance validation pending.

The frozen remediation defaults are a shared two-lane 32-frame selective-repeat window, `ENDPOINT_BURST_FRAMES=32`, `ACK_THRESHOLD=32`, a 1 ms ACK maximum delay, and a 4,352-cycle (68 us) direction guard. The direction guard is the hardware-selected 4,096-cycle post-TX margin plus the separate 256-cycle idle qualification. Receiver-credit pressure, a blocking gap, fault/control, explicit stop, or timer expiry may close the window early. Every physical retransmission carries an explicit DATA-to-ACK direction boundary, guaranteeing a fresh cumulative ACK after a late gap fill even when an object-final frame arrived earlier on the other lane. An object boundary does not itself request an ACK, reverse optical direction, re-prime the receiver, drain the pipeline, or exchange an optical ready pulse.

The hardware run preserved at commit `c171ddd4f498608292f0d29ca908c48372893774` disproved the earlier complete-next-frame reservation throughput model. In its first 30-second ACK-tuning case, direct receiver telemetry recorded 30,674 accepted DATA frames in 25.058 seconds, an aggregate 247-byte L1 upper bound of 2,418,861 bit/s. The sender received 1,039 ACKs, or 29.52 DATA frames per ACK, so ACK density was not the limiting factor. The endpoints remained healthy and running; the 16 MiB object simply could not finish before the test timeout. The preserved diagnosis is `evidence/generated/p10_1r_ack_tuning_failure_diagnosis.json`.

The root cause was conservative repeated reservation of all 8,928 high cycles for a maximum DATA frame before its first symbol. Old pulses that would expire while the new 558 us frame was in flight could not contribute headroom, producing approximately 1.4 ms lane start spacing. P10.1R now uses a qualified frame-boundary schedule for the independent AX7020 endpoints. At 64 MHz, a maximum frame occupies 1,116 32-cycle symbol slots and the fixed post-frame guard is 17,984 cycles, or 562 slots. Any 64,000-cycle/2,000-slot window intersects at most 1,439 pulses, including one conservative boundary intersection. At eight high cycles per pulse, the bound is 11,512 cycles, eight cycles below the exact accountant's strict 11,520-cycle 18% threshold. A 17,952-cycle/561-slot guard is rejected because its conservative bound can reach 11,520 cycles.

Qualification is per physical lane. The first DATA frame waits for an empty exact-duty history; a complete DATA frame establishes the schedule. Reset, raw mode, abort, disarm, full shutdown, a safety fault, object failure, or an object-direction change invalidates it. ACK frames retain full-frame headroom admission, and the P9 monolithic role retains its historical 20,480-cycle guard plus complete-frame reservation. The exact clock-aligned accountant, `<20%` hard limit, `<=18%` target throttle, 1 us continuous-high guard, final TX kill, SD/Mode behavior, and the single `GLOBAL_PERMIT` path are unchanged and remain final backstops.

The PS runtime uses four 256 KiB buffers, a 32-entry SG descriptor ring, batches of up to eight descriptors, and one board-autonomous stream command per direction. Four buffers/descriptors are prepared before the first object. During transfer, released slots are refilled, object N+1 is started before CPU integrity verification of N, and incremental CRC32/SHA256 plus atomic stream commit remain enforced. The single final stream-level coordination exchange replaces per-object optical ready round trips. Host control is outside the per-object fast path; the contract caps blocking commands at four per direction and requires at least 1,000 segments per command.

The corrected airtime model includes two 4 Mbit/s lanes, 247-byte L1 payloads, 215 useful RFAP bytes per frame, the proved 17,984-cycle duty guard, a conservative 64-cycle launch allowance, DATA/ACK airtime, the 68 us direction guard, PER/retry, and DMA/PS overlap. The DATA-module duty recovery overlaps the opposite-module DATA-to-ACK-to-DATA turnaround, so the model uses the slower elapsed path instead of adding concurrent waits. It predicts a 840 us maximum-frame start period, a 13,440 us bundle cycle, and 4,073,947 useful bit/s after the frozen retry and overlap factors in either direction. This is an offline feasibility result with about 1.85% margin, not a hardware PASS.

Any change to RTL, protocol, firmware, XSA, BSP, or ELF creates new immutable artifacts and invalidates inheritance from prior P10/P10.1 hardware results.
