# P8E timing, CDC, reset, and RAM architecture

P8E replaces single-cycle 32/64-entry reductions with bounded engines. TX candidate selection inspects one entry per cycle while tracking preferred and fallback classes; ACK validation, reclaim, and base advance are separate bounded phases; timeout maintenance uses one shared timer cursor with absolute expiries. Allocation remains independent of ACK reclaim, and an ACK snapshot cannot reclaim a later allocation. RX stores a registered presence/SACK bitmap and advances at most one delivered base entry per cycle.

The weighted scheduler captures eligibility, cost, deficit inputs, path epoch, and ordinary permit state at a request boundary, then performs a registered one-hot selection. `ir_data_plane_top` still rechecks live mapping, credit, permit, arm, and kill at the physical-attempt handshake. The P8C raw `GLOBAL_PERMIT=0` path remains the final direct TX kill and is not delayed by this pipeline.

Payload and descriptor data arrays are not cleared. Valid/owner metadata and descriptor generations make stale content unreachable. `ir_shared_payload_store` uses synchronously reset read/write command registers so no asynchronously reset owner bit drives a RAMB enable; this closes REQP-1839 structurally rather than with a waiver.

Endpoint reset assertion is asynchronous and endpoint-wide. `reset_sync` provides three-stage synchronous deassertion separately for protocol, AXI DMA, and AXI-Lite domains. Sparse pulse/level crossings use the common `pulse_sync` and `level_sync`; sustained streams reserve the Gray-pointer `async_fifo`. Fixed and rotating endpoint resets are independent, while all local domains of one endpoint share the assertion source. Descriptor generations reject stale completions after abort/reset.

The expected TX bounds are one window scan for attempt selection, `SACK_BITS + WINDOW_SIZE + WINDOW_SIZE` cycles for worst-case queued ACK validation/reclaim/base advance, and at most one window revolution beyond RTO for timeout detection. These latencies change scheduling response time, not sequence-wrap, SACK, retry-migration, completion, or outstanding-capacity semantics.

Vivado methodology warnings are classified without suppression. `LUTAR-1` is the intentional fail-low asynchronous assertion path: raw permit/reset can only clear permit synchronization/filtering and endpoint arm state, while raw permit low separately gates final physical Txd. `TIMING-18` records external I/O delays that are not yet canonical; P8E does not fabricate zero-nanosecond delays. Internal endpoints remain fully constrained, Z7020 board timing stays `PENDING_D12`, and Z7010 external interface timing remains a platform follow-up. Any other methodology warning rule is an acceptance failure.
